# vacation-tracker — сервис учёта отпусков (задание 13)

Разработчик: Camilla Abdulla. Модель и инструмент: Claude Sonnet 5.5 через claude.ai (чат). Взят потому, что быстро итерируется по предметным правилам и умеет сразу запускать тесты. Шаблонов и чужих решений нет; используются зависимости из `requirements.txt` и `package.json`, структура frontend — стандартная для Vite.

## Стек и почему
- **Backend: Python + FastAPI + psycopg 3** — типизированные схемы запросов, автодокументация `/docs`, чистый SQL без ORM (нужны пересечение интервалов, `on conflict do nothing`, `pg_notify`).
- **Frontend: React + Vite** — отдельное приложение, общается с backend по HTTP/JSON и SSE. Шрифт Montserrat (пакет `@fontsource-variable/montserrat`, подключён локально, интернет для шрифта не нужен). Палитра сине-жёлтая: у HR жёлтая шапка и жёлтые акценты, у сотрудника и руководителя синяя шапка. В календаре синий цвет — согласовано, жёлтый с штриховкой — на рассмотрении. Экраны: вход с демо-аккаунтами в один клик; сотрудник — остаток, прогноз на дату, форма заявки, мои заявки; руководитель — согласование с предупреждением о пересечениях и обязательной причиной отказа; HR — сводка, остатки с правкой даты выхода, календарь компании по командам.
- **БД: PostgreSQL.** Для локального запуска без Docker backend сам поднимает встроенный PostgreSQL через пакет `pixeltable-pgserver` (форк `pgserver`; в среде Claude он ставит PostgreSQL 18.4, данные в `.pgdata/`). Для боевого режима задайте `DATABASE_URL`. **Запасной режим:** если встроенный PostgreSQL не запустился (на одном Windows он падал с кодом `0xC0000135`), backend сам переходит на SQLite (файл `.vacation.sqlite3`) и пишет об этом в консоль, в `/api/v1/health` и жёлтой полосой в интерфейсе. Принудительно: `VAC_DB=sqlite`.

## Быстрый запуск (Windows)
Нужны **Python 3.10 или новее** (проверялось на 3.12; для 3.13 и 3.14 есть все пакеты под Windows, но на самом 3.14 запуск не проверялся) и **Node.js 20 LTS**. Docker и отдельный PostgreSQL не нужны.
Дважды щёлкните **`start.bat`** (или запустите его из cmd). Откроются два окна: backend :8000 и frontend :5173; первый запуск 1–3 минуты. Войти: `ivan`, `olga`, `boss` (руководитель), `hr`, пароль `demo`.
Если окно упало — текст ошибки останется на экране. Проверка backend: http://localhost:8000/api/v1/health.
Вручную (cmd): `cd backend`, `py -3.14 -m venv .venv` (или `py -3.12`), `.venv\Scripts\pip install -r requirements.txt`, `.venv\Scripts\python -m uvicorn app.main:app --port 8000`; в другом окне `cd frontend`, `npm.cmd install`, `npm.cmd run dev`.
Свой PostgreSQL вместо встроенного: задайте переменную `DATABASE_URL` (если она задана, запасной SQLite не включается и ошибка подключения видна сразу). Встроенный Postgres нельзя запускать от имени администратора.
Какая база работает сейчас: `http://localhost:8000/api/v1/health` → поле `db` (`postgres-embedded`, `postgres` или `sqlite`).

## Правила
- Накопление: `floor(28 × отработанные_дни / 365)`; остаток считается функцией, поэтому смена даты выхода пересчитывает всё сама.
- Заявка: до 3 частей, хотя бы одна от 14 дней, остальные от 5, части не пересекаются, задним числом нельзя. Суммарные дни по хронологии не должны превышать накопленное к началу каждой части. В календарном году (по дате начала части) всего не больше 4 частей по заявкам «на рассмотрении» и «согласован»; отмена освобождает лимит.
- Согласование: отклонение требует комментария; при согласовании видны пересечения с согласованными отпусками команды.
- Отмена до начала возвращает все дни; после начала остаётся использованное по сегодня включительно. Перенос — атомарно отмена + новая заявка.
- Смена даты выхода: остаток пересчитывается сразу. Заявки, которые перестали покрываться накоплением, автоматически не отменяются: сотрудник, его руководитель и HR получают по одному уведомлению на заявку, у HR в таблице появляется пометка с причиной.
- Вход: токен в БД (хеш), срок 7 дней; перезапуск backend не разлогинивает. Уведомления можно отметить прочитанными, у колокольчика счётчик непрочитанных.
- Уведомления и напоминания «ровно одно» гарантирует `unique(type, vacation_id, recipient_id)`. Напоминание за `REMIND_DAYS` дней (по умолчанию 3). Почта эмулируется: запись в БД + строка в логе.
- Календари обновляются без перезагрузки: SSE поверх Postgres LISTEN/NOTIFY; в режиме SQLite вместо NOTIFY используется вызов внутри процесса (работает при одном процессе backend).

## Тесты
`cd backend; .\.venv\Scripts\python -m pytest -q` — 38 тестов: юнит-тесты правил и интеграционные на реальном HTTP-сервере (гонка двух согласований, SSE между двумя сессиями и после обрыва соединения слушателя, напоминание ровно один раз, годовой лимит, пересмотр после смены даты выхода, сессии, миграции, переход на SQLite при сбое встроенного PostgreSQL). Тесты сами поднимают временную БД. Те же тесты на запасной SQLite: `$env:VAC_DB="sqlite"; python -m pytest -q`. Вывод прогона в среде Claude лежит в `TEST_RESULTS.txt`.
Сквозные тесты интерфейса в браузере: `e2e/` (инструкция в `e2e/README.md`), результат — `E2E_RESULTS.txt`, скриншоты — `docs/screenshots/` (сняты в среде Claude на запасной SQLite).

## Состояние (честно)
- **Проверено:** тесты backend прошли дважды — 38 на встроенном PostgreSQL 18.4 и 37 (один пропущен: нужен LISTEN) на SQLite (Linux, Python 3.12, сессия Claude, `TEST_RESULTS.txt`). Frontend: `npm run build` (типы и сборка) проходит; 5 сквозных тестов в Chromium (Playwright) прошли дважды подряд (`E2E_RESULTS.txt`): ошибка правил в форме, заявка и обновление бейджа у руководителя без перезагрузки, отказ с причиной, правка даты выхода у HR, счётчик непрочитанных уведомлений, мобильная ширина 390 px.
- **Не проверено:** запуск `start.bat` на Windows пользователя после добавления запасного режима SQLite и ручной прогон интерфейса в двух вкладках — отметьте результат в `docs/TEST_PLAN.md`. Известно, что встроенный PostgreSQL на одном Windows (Python 3.14) не запустился (`postgres.exe` завершился с `0xC0000135`), причина не установлена.
- **Сделано сверх исходного плана:** годовой лимит частей, уведомления о пересмотре заявок при смене даты выхода, «прочитано» у уведомлений, сессии в БД, версионированные SQL-миграции (вместо Alembic: в проекте нет SQLAlchemy), сквозные тесты интерфейса.
- **Не сделано:** автоматическое изменение статуса заявок при смене даты выхода (только уведомления и пометка), откат миграций (down), юнит-тесты отдельных компонентов React, проверка на нескольких процессах backend.
- **Ограничения безопасности:** CORS открыт для демо; пароли с солью (PBKDF2), но без ограничения попыток входа; токен передаётся в адресе SSE-запроса (`/events?token=`), потому что `EventSource` не умеет заголовки; просроченные сессии не удаляются из БД автоматически.

## Следующим заходом
Запуск обычного PostgreSQL на проверяющем Windows без запасного режима, смена статуса заявок при пересмотре с повторным согласованием, ограничение попыток входа, очистка просроченных сессий, JWT/SSO, реальная отправка почты, производственный календарь (праздники не должны считаться днями отпуска).
