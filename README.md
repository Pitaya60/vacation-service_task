# vacation-tracker — сервис учёта отпусков (задание 13)

Разработчик: Camilla Abdulla. Модель и инструмент: Claude Sonnet 5.5 через claude.ai (чат). Взят потому, что быстро итерируется по предметным правилам и умеет сразу запускать тесты. Шаблонов и чужих решений нет; используются зависимости из `requirements.txt` и `package.json`, структура frontend — стандартная для Vite.

## Стек и почему
- **Backend: Python + FastAPI + psycopg 3** — типизированные схемы запросов, автодокументация `/docs`, чистый SQL без ORM (нужны пересечение интервалов, `on conflict do nothing`, `pg_notify`).
- **Frontend: React + Vite** — отдельное приложение, общается с backend по HTTP/JSON и SSE.
- **БД: PostgreSQL.** Для локального запуска без Docker backend сам поднимает встроенный PostgreSQL через пакет `pixeltable-pgserver` (форк `pgserver`; в среде Claude он ставит PostgreSQL 18.4, данные в `.pgdata/`). Для боевого режима задайте `DATABASE_URL`. **Запасной режим:** если встроенный PostgreSQL не запустился (на одном Windows он падал с кодом `0xC0000135`), backend сам переходит на SQLite (файл `.vacation.sqlite3`) и пишет об этом в консоль, в `/api/v1/health` и жёлтой полосой в интерфейсе. Принудительно: `VAC_DB=sqlite`.

## Быстрый запуск (Windows)
Нужны **Python 3.10 или новее** (проверялось на 3.12; для 3.13 и 3.14 есть все пакеты под Windows, но на самом 3.14 запуск не проверялся) и **Node.js 20 LTS**. Docker и отдельный PostgreSQL не нужны.
Дважды щёлкните **`start.bat`** (или запустите его из cmd). Откроются два окна: backend :8000 и frontend :5173; первый запуск 1–3 минуты. Войти: `ivan`, `olga`, `boss` (руководитель), `hr`, пароль `demo`.
Если окно упало — текст ошибки останется на экране. Проверка backend: http://localhost:8000/api/v1/health.
Вручную (cmd): `cd backend`, `py -3.14 -m venv .venv` (или `py -3.12`), `.venv\Scripts\pip install -r requirements.txt`, `.venv\Scripts\python -m uvicorn app.main:app --port 8000`; в другом окне `cd frontend`, `npm.cmd install`, `npm.cmd run dev`.
Свой PostgreSQL вместо встроенного: задайте переменную `DATABASE_URL` (если она задана, запасной SQLite не включается и ошибка подключения видна сразу). Встроенный Postgres нельзя запускать от имени администратора.
Какая база работает сейчас: `http://localhost:8000/api/v1/health` → поле `db` (`postgres-embedded`, `postgres` или `sqlite`).

## Правила
- Накопление: `floor(28 × отработанные_дни / 365)`; остаток считается функцией, поэтому смена даты выхода пересчитывает всё сама.
- Заявка: до 3 частей, хотя бы одна от 14 дней, остальные от 5, части не пересекаются, задним числом нельзя. Суммарные дни по хронологии не должны превышать накопленное к началу каждой части.
- Согласование: отклонение требует комментария; при согласовании видны пересечения с согласованными отпусками команды.
- Отмена до начала возвращает все дни; после начала остаётся использованное по сегодня включительно. Перенос — атомарно отмена + новая заявка.
- Уведомления и напоминания «ровно одно» гарантирует `unique(type, vacation_id, recipient_id)`. Напоминание за `REMIND_DAYS` дней (по умолчанию 3). Почта эмулируется: запись в БД + строка в логе.
- Календари обновляются без перезагрузки: SSE поверх Postgres LISTEN/NOTIFY; в режиме SQLite вместо NOTIFY используется вызов внутри процесса (работает при одном процессе backend).

## Тесты
`cd backend; .\.venv\Scripts\python -m pytest -q` — 12 юнит-тестов правил и 17 интеграционных/e2e тестов на реальном HTTP-сервере (гонка двух согласований, SSE между двумя сессиями, напоминание ровно один раз, переход на SQLite при сбое встроенного PostgreSQL). Тесты сами поднимают временную БД. Те же тесты на запасной SQLite: `$env:VAC_DB="sqlite"; python -m pytest -q`. Вывод прогона в среде Claude лежит в `TEST_RESULTS.txt`.

## Состояние (честно)
- **Проверено:** 29 тестов backend прошли дважды — на встроенном PostgreSQL 18.4 и на SQLite (Linux, Python 3.12, сессия Claude, см. `TEST_RESULTS.txt`). Frontend собирается (`vite build`) без ошибок типов; календарь — месячная сетка (зелёный согласовано, оранжевый на рассмотрении).
- **Не проверено:** запуск `start.bat` на Windows пользователя после добавления запасного режима SQLite и ручной прогон интерфейса в двух вкладках — отметьте результат в `docs/TEST_PLAN.md`. Известно, что встроенный PostgreSQL на одном Windows (Python 3.14) не запустился (`postgres.exe` завершился с `0xC0000135`), причина не установлена.
- **Не сделано:** годовой лимит частей, автоматический пересмотр заявок при смене даты выхода (HR видит флаг «требует внимания»), миграции Alembic (схема применяется скриптом `schema.sql` при старте), тесты frontend.
- **Ограничения безопасности:** токены хранятся в памяти процесса (после перезапуска нужно войти снова), CORS открыт для демо, пароли с солью (PBKDF2), но без ограничения попыток входа.

## Следующим заходом
