# Сервис учёта отпусков (задание 13)

**Как сделано:** Claude Sonnet 5.5 через claude.ai (чат, без агентного режима); модель выбрана ради скорости итераций по предметным правилам. Шаблонов и чужих решений нет, кроме зависимостей и структуры Vite.

## Запуск
Нужны Docker и docker compose. `docker compose up`, затем http://localhost:5173 (API на :3001).
Демо-вход (пароль `demo`): `hr`, `boss` (руководитель Ивана и Ольги), `ivan`, `olga`.
Тесты правил: `cd backend && npm i && npm test`. Откройте две вкладки под разными пользователями: календарь и уведомления обновятся через SSE.

## Стек
Node.js + Fastify + `pg` (backend), React + Vite (frontend), PostgreSQL 16. SSE работает на Postgres LISTEN/NOTIFY, поэтому события доходят до всех инстансов backend.

## Правила (RULES)
- Накопление: `floor(28 * отработанные_дни / 365)`, остаток считается функцией, не хранится: смена даты выхода пересчитывает всё автоматически.
- Заявка: до 3 частей, хотя бы одна от 14 дней, остальные от 5, части не пересекаются. Нарастающий итог дней по хронологии не должен превышать накопленное к началу каждой части.
- Отклонение требует комментария. Отмена до начала возвращает все дни, после начала остаётся использованное по сегодняшний день включительно.
- Перенос: в одной транзакции отмена старой заявки и новая заявка на согласование.
- Уведомления и напоминания: «ровно одно» гарантирует `unique(type, vacation_id, recipient_id)`. Напоминание за `REMIND_DAYS` дней (по умолчанию 3), планировщик раз в минуту. Почта эмулируется записью в БД и логом backend.

## Состояние (честно)
- **Не запускалось и не проверялось:** у меня не было Postgres и Docker. Код написан, но ни один тест не прогонялся, возможны опечатки.
- Есть только юнит-тесты чистых правил. Интеграционных тестов на Postgres, теста гонки уведомлений и e2e для двух сессий нет.
- Вход упрощённый: токены лежат в памяти backend, пароль хранится как sha256 без соли (демо).
- Лимит «3 части в году» не реализован, ограничение действует на одну заявку.
- UI без стилей, список вместо визуального календаря.
- При смене даты выхода HR видит флаг «требует внимания», но заявки не пересматриваются автоматически.
- Миграций нет, схема применяется только при первом создании БД.
