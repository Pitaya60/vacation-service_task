# API Design — `/api/v1`, HTTP/JSON, интерактивная документация на http://localhost:8000/docs

Авторизация: `Authorization: Bearer <token>` из `POST /login`. Ошибки: `{"error": "текст"}` — текст можно показывать пользователю как есть (в том числе для ошибок валидации полей).

| Метод и путь | Назначение | Ошибки |
|---|---|---|
| GET /health | `{status, db, warning, version}`: какая БД работает (`postgres-embedded`, `postgres`, `sqlite`) | |
| POST /login, POST /logout | вход (токен хранится в БД в виде хеша, срок 7 дней; при входе просроченные сессии удаляются); выход | 401; 429 после 5 неудачных попыток на логин за 5 минут (заголовок `Retry-After`); 422 пустые поля |
| GET /me | профиль, `today`, `approvers` — имена тех, кто согласует заявки пользователя | 401 |
| GET /balance?date= | на дату: `accrued` накоплено, `used` (старое имя `reserved`) дни начавшихся к дате частей, `planned` дни более поздних заявок, `available = accrued − used`, `free` — сколько ещё можно запланировать с этой даты с учётом уже поданных заявок, `annual` = 28 | 401 |
| POST /vacations `{parts:[{start,end}]}` | заявка; уведомление получает руководитель, а если его нет (руководитель отдела, HR) — другие сотрудники HR | 422 правила (в том числе не больше 4 частей в календарном году; «Некому согласовать», если нет ни руководителя, ни другого HR), 401 |
| POST /vacations/{id}/cancel | отмена; согласующий получает уведомление; даты остаются в истории, `cancelled_on` = сегодня | 404, 409 |
| POST /vacations/{id}/reschedule | перенос (атомарно) | 404, 409, 422 |
| POST /vacations/{id}/decision `{approve, comment}` | согласование: руководитель сотрудника; для сотрудников без руководителя — HR (не сам себе); записываются `decided_at`, `decided_by` | 403 не ваш сотрудник, 409 уже рассмотрена, 422 нет комментария при отказе или он длиннее 500 символов |
| GET /vacations | свои заявки и заявки, которые согласует пользователь: подчинённых, а у HR ещё и сотрудников без руководителя. Поля: `parts`, `days`, `created_at`, `decided_at`, `decided_by_name`, `cancelled_on`, `replaces_id`; у ожидающих решения чужих — `conflicts` и `balance_after` (`free` сотрудника с учётом этой заявки) | |
| GET /calendar?scope=team\|company | календарь (company только HR) | 403 |
| GET /notifications, POST /notifications/read | уведомления пользователя (`type`: `new_request`, `decision`, `cancelled`, `reminder`, `balance_review`; `read_at`); отметить все прочитанными | |
| GET /hr/balances | по каждому сотруднику: `accrued`, `used`, `planned`, `free`, `available`, `onVacation`, `manager`, `needsAttention`, `problem` | 403 |
| PATCH /users/{id}/hire-date `{hire_date}` | смена даты выхода (HR); после неё уведомления по заявкам, которые перестали покрываться накоплением | 403, 404, 422 дата в будущем |
| GET /events?token= | SSE: событие `cal` при любом изменении (пачка изменений склеивается в одно событие), `retry: 3000` | 401 |

**Напоминания:** фоновая задача раз в минуту; за `REMIND_DAYS` дней (по умолчанию 3) и ближе до начала согласованного отпуска сотрудник и согласующие получают по одному напоминанию (текст называет реальное число дней).

**Между клиентами:** изменение → `pg_notify('cal')` (в режиме SQLite — вызов в процессе) → SSE всем подключённым → клиент перечитывает данные. **Дубли и гонки:** уникальный ключ уведомлений; параллельные решения и повторная отмена — 409; две одновременные заявки одного сотрудника выстраиваются в очередь блокировкой строки сотрудника (PostgreSQL), поэтому обе не проходят проверку остатка «вслепую».

**CORS:** разрешены адреса из `CORS_ORIGINS` (по умолчанию dev-сервер `:5173` и `vite preview` `:4173`).
